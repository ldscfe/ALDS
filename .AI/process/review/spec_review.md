# Spec Review Checklist

Used when creating or changing behavioral contracts.

## Review Focus

1. Is behavior observable and testable
2. Are inputs, outputs, error conditions clear
3. Are edge cases covered
4. Is expression implementation-independent where possible
5. Is it consistent with existing architecture and invariants

## Result Types

- `approved`
- `needs_update`
- `rejected`
